# Dataset chunk format — `pi-atlas-packed-v1` + web manifest

Stage 2 prototype specification. Defines how the existing 1-billion-digit packed
dataset is described to, and delivered to, the browser without changing a single
packed byte.

## 1. Packed chunk format (unchanged reference format)

- Two decimal digits per byte, **big nibble = even 0-based digit index**.
  Byte value `(d0 << 4) | d1` where `d0`/`d1` are digit values 0–9.
- Dataset contains **only digits after the decimal point**; the leading `3` is
  never stored. A digit at 0-based offset `d` is at 1-based position `d + 1`.
- Chunk `i` is `chunks/chunk_%05d.bin`. All chunks except the last have
  `chunk_digits` digits; the last may be shorter (always even).
- Source of truth: `scripts/pack_dataset.py`, Rust `service/crates/core/src/pack.rs`.

## 2. Browser web manifest — `pi-atlas-web-manifest-v1`

Generated by `scripts/make_web_dataset.py` from the packed dataset's
`manifest.json`. It is a thin descriptor: it adds network/version fields but
reuses the exact SHA-256 values the Rust service already verifies.

```json
{
  "version": 1,
  "format": "pi-atlas-packed-v1",
  "datasetId": "pi-1b-2026",
  "totalDigits": 1000000000,
  "chunkDigits": 10000000,
  "chunkCount": 100,
  "packedBytes": 500000000,
  "firstDigits": "14159265358979...",
  "sha256Packed": "<sha256 of all packed chunks concatenated>",
  "baseUrl": "dataset/1b/chunks/",
  "filenameTemplate": "chunk_{index:05d}.bin",
  "chunks": [
    {
      "index": 0,
      "file": "chunk_00000.bin",
      "digits": 10000000,
      "bytes": 5000000,
      "packedOffset": 0,
      "digitOffset": 0,
      "sha256": "<sha256 of chunk_00000.bin>"
    }
  ],
  "checkpoints": [{ "query": "12", "firstPosition": 148 }],
  "searchIndex": {
    "kind": "none",
    "note": "No persistent index; full searches scan all chunks sequentially."
  }
}
```

Field semantics:

| Field | Meaning |
| --- | --- |
| `version` | Web-manifest schema version. Client accepts only `1`. |
| `format` | Packed format id; client accepts only `pi-atlas-packed-v1`. |
| `datasetId` | Stable identity. Changing it invalidates every cached chunk. |
| `totalDigits` / `chunkDigits` / `chunkCount` | Dataset geometry; all even (digits) and self-consistent. |
| `packedBytes` | Sum of all chunk byte lengths = `totalDigits / 2`. |
| `firstDigits` | First 64 digits after the point; integrity sanity check. |
| `sha256Packed` | SHA-256 over the concatenation of all packed chunks. |
| `baseUrl` | URL prefix for chunk files, relative to the document (e.g. `dataset/1b/chunks/`). Under Pages this is `/pi-atlas/dataset/1b/chunks/`. |
| `filenameTemplate` | Informational template for chunk filenames. |
| `chunks[]` | Per-chunk `index`, `file`, `digits`, `bytes`, `packedOffset` (byte offset in concatenated stream), `digitOffset` (0-based digit offset of first digit), `sha256`. |
| `checkpoints` | Known-answer pairs (e.g. `12` → 148) for quick integrity/correctness probes. |
| `searchIndex` | Index metadata. `kind: "none"` means a full search must scan every chunk. |

## 3. Integrity rules (enforced by client and generator)

1. Manifest: `chunkCount == ceil(totalDigits / chunkDigits)`, digit/byte sums
   equal totals, per-chunk `bytes == digits / 2`, contiguous `packedOffset` and
   `digitOffset`, 64-hex SHA-256 values.
2. On download: `arrayBuffer.byteLength == chunk.bytes`, then WebCrypto
   `SHA-256(bytes) == chunk.sha256`. A mismatch raises `ChunkIntegrityError`;
   the chunk is **not cached** and the caller sees a dataset-integrity failure.
3. Optional whole-file check: hash chunks in index order, compare to
   `sha256Packed` (done by the generator; browser omits it to avoid re-reading
   all chunks).

## 4. Delivery & caching contract

- Chunks are **independent static files** — no reliance on HTTP Range requests.
- `ChunkLoader` downloads only requested chunks, deduplicates in-flight requests,
  verifies before caching, and bounds memory with an LRU (`maxCachedChunks`).
- Cache key = `datasetId + chunk index`. Persistent (IndexedDB) caching is added
  in Stage 6; this prototype is memory-only.
- No compression in v1: packed digits are already dense and random; per-chunk
  compression would need independent decompressibility and is deferred to
  Stage 11 benchmarking.

## 5. Generation / validation commands

```bash
# From a packed dataset directory (digit file packed by pack_dataset.py):
python3 scripts/pack_dataset.py --input public/pi-2m.txt \
    --output-dir /tmp/pi-atlas-e2e-data --chunk-digits 1000000
python3 scripts/make_web_dataset.py \
    --input /tmp/pi-atlas-e2e-data \
    --output-dir /tmp/pi-atlas-web-data \
    --dataset-id pi-2m-test --base-url dataset/2m/chunks/

# 1B (run locally; never commit the ~477 MiB of chunks unless deploying that tree):
python3 scripts/make_web_dataset.py \
    --input /home/megalith/pi-atlas-build/data-1b \
    --output-dir /home/megalith/pi-atlas-web/1b \
    --dataset-id pi-1b-2026 --base-url dataset/1b/chunks/
```

TypeScript API: `src/data/browser/{manifest,sha256,chunkLoader,packedDigits}.ts`.
